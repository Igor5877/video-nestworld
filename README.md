# World Utilities 1.3.12

Відеоекрани для Minecraft **1.20.1 / Forge 47.4.6+**, Java 17.
На клієнті потрібен **WaterMedia 2.1.37** (залежність, з якою перевірено збірку).
Мод і WaterMedia використовують VLC для декодування відео.

## Встановлення

1. Заміни старий JAR мода у `mods` на `world-utilities-1.3.12.jar`.
   Стара збірка могла називатися `examplemod-1.0.0.jar`; не залишай обидві.
2. Для сервера встанови цю саму версію Video Nestworld на сервер і всім гравцям.
   WaterMedia потрібен на клієнтах. Для версії 1.3.10 сервер і клієнти мають бути оновлені разом
   (мережевий протокол — 5).
3. Каталог відео зберігається у `config/videos.json` сервера або одиночного профілю.
   Після редагування оператор може виконати `/reloadvideo`.

Для завантаження аніме з AniUA оператор сервера виконує `/aniua <slug>`. Slug треба
скопіювати з URL AniUA повністю, разом із суфіксом, наприклад
`/aniua neko-no-ongaeshi-8f8f88`. Сервер асинхронно звертається до публічного AniUA API,
додає епізоди як категорію `AniUA: <slug>` і синхронізує її гравцям. Код Android-
застосунку AniUA, ключі та токени в мод не вбудовуються.

## Як побудувати екран

- Видай собі блок командою `/give @s nestworldvideo:video_screen`.
  Предмети екрана й пульта не додаються у творчий інвентар, рецептів і випадіння
  після руйнування немає.
- Виклади суцільну вертикальну стіну-прямокутник від **1×1 до 100×100**.
  Усі блоки мають дивитися в один бік. При добудові збоку або зверху новий блок
  успадковує напрямок сусіднього. Для встановлення блока на екран утримуй Shift.
- Натисни ПКМ на будь-якому блоці → **Екран → Об’єднати**.
  Перед об’єднанням побачиш розмір і схему. Дірки, виступи, різні напрямки
  та перевищення 100 блоків по будь-якій стороні відхиляються.
- **Роз’єднати** зупиняє відео й повертає блоки до окремих екранів.
  Руйнування частини стіни також роз’єднує екран. Щоб добудувати або відремонтувати
  стіну, розмісти блоки та повторно натисни **Об’єднати**.
- Усі чанки стіни та її найближчого оточення мають бути завантажені під час
  об’єднання. Мод не завантажує їх примусово. Для великого екрана збільш дальність
  відображення; серверна дальність також має охоплювати стіну.

## Керування

Вкладка **Пошук AniUA**: введи частину назви (від двох символів) та натисни
**Знайти** або Enter. Вибери потрібний реліз у списку результатів, потім озвучку
та серію. Пошук показує до 50 збігів; для ширшого запиту уточни назву.
Кнопка **Сезони** відкриває пов’язані сезони й фільми з каталогу Hikka.
Постер вибраного аніме завантажується у фоні; відсутнє зображення має заглушку.
Номер сезону показується, коли він зазначений у назві/slug релізу; календарний
сезон API (літо/зима) не використовується як номер сезону серіалу.

Серії впорядковані за номером. Недоступний відеопотік позначається на кнопці;
якщо є кілька джерел для однієї серії, можна вибрати джерело окремо.
Натискання на серію вибирає відео; кнопка **Відтворити** запускає його.
**Бібліотека** містить збережені аніме й категорії локального каталогу.
Старі записи читаються без ручного перенесення; повторний вибір аніме через
пошук оновлює метадані, постер і список серій.
Якщо старий AniUA-каталог містить порожні посилання, його відкриття в бібліотеці
автоматично повторно завантажує адреси потоків.
Пауза зберігає позицію; зупинка звільняє програвач і наступний запуск починається спочатку.
Гучність `−` / `+` змінюється лише для твого клієнта.
Гаряча клавіша керування відкриває екран під прицілом, як ПКМ.
Новий браузер аніме має український інтерфейс.

На публічному сервері пошук Hikka кешується на 5 хвилин, дані релізу — на 15 хвилин,
а список епізодів AniUA — на 15 хвилин. Одночасні однакові запити об'єднуються, тому відкриття одного аніме
багатьма гравцями не створює окремий запит до API для кожного гравця. Відео не
проксіюється через сервер: клієнт отримує прямий HLS-потік від провайдера.

Одна стіна 100×100 блоків використовує один програвач на клієнті. Для окремих
екранів клієнт за замовчуванням відкриває не більше 8 потоків одночасно і лише
в межах 128 блоків; дальні екрани запускаються, коли звільняється слот. Ліміти
можна змінити у клієнтському `config/nestworldvideo-client.toml`:
`max_active_streams` (1–64) та `max_stream_distance` (16–512).

Один об’єднаний екран використовує один програвач та одне відеополотно;
пропорції відео зберігаються з чорними полями. 10 000 блоків усе одно мають
вартість зберігання, синхронізації й звичайного відображення блоків.
Клієнт надсилає heartbeat лише поки має активний програвач. У GUI показується
кількість і список таких глядачів; на кожен heartbeat (раз на 5 секунд) сервер відповідає
позицією спільної шкали часу та своїм годинником, тому гравці одного екрана синхронізуються
без зайвих пакетів.

Синхронізація: сервер рахує позицію відео за реальним годинником (не за ігровими тіками, які
сповільнюються, коли сервер лагає). Клієнт оцінює різницю годинників як NTP — heartbeat несе
час відправлення, і відповідь з найкоротшим шляхом туди-назад дає найточнішу оцінку. Розходження
до 30 мс вважається «разом»; від 30 мс до 2 с декодер FFmpeg вирівнює його, граючи до 3 % швидше
або повільніше (звук через OpenAL pitch, на слух майже непомітно); понад 2 с — перемотка
(не частіше ніж раз на 5 с). Пакети, що не змінюють час (повтор, автонаступне, relay), декодер
не рухають. VLC (WaterMedia) підтримує лише перемотку.
Старт після стопу, наступна серія чи повтор починаються зі спільним відліком 2,5 с (усі встигають
відкрити потік), перемотка ±10 с — із запасом 0,3 с; програвач чекає на першому кадрі, поки спільна
шкала до нього дійде, тож усі рушають разом. Локальний кеш потоку (`stream_cache`) робить перемотку
на ±10 с майже миттєвою (~0,15 с). Режим декодера «Авто» спершу пробує FFmpeg, VLC — запасний.

Кожен гравець усе одно отримує власний прямий HLS-потік від відеосервера. Для сотень
глядачів джерело відео треба поставити за CDN або HLS-relay: Minecraft-сервер не
повинен проксувати ці байти.

## Формат каталогу

```json
{
  "categories": [
    {
      "name": "Кіно",
      "videos": [
        {
          "title": "Назва фільму",
          "description": "Короткий опис",
          "url": "https://your-host.example/movie.mp4"
        }
      ]
    }
  ]
}
```

Потрібне пряме посилання на медіафайл/потік, доступне кожному гравцю.
Адреса сторінки сайту може не бути адресою відео. Клієнти можуть вибирати лише
відео з серверного каталогу. Локальні шляхи придатні для одиночної тестової гри;
на сервері використовуй HTTP(S)-адреси спільного хостингу.

## Збірка й перевірка

```bash
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./gradlew clean build
```

Результат: `build/libs/world-utilities-1.3.12.jar`.

У 1.3.11 керування VLC чекає першого декодованого кадру. Якщо потік завершився
або повідомив про помилку до першого кадру, клієнт один раз повторює запуск
через секунду. Звичайне завершення відео не запускає його повторно.
Деталі перевірки Windows: [діагностика запуску](docs/windows-playback-startup.md).
Сцена `src/selftest` підключається тільки з `-Pselftest` і не входить до релізу.
`runClient -Pselftest` використовує окремий `build/selftest-run`, приховує вікно
та створює тестовий світ. Для повного тесту відтворення потрібні українська мова,
тестовий каталог і локальний `test-pattern.mp4` у цьому профілі; інструкції —
у `tools/prepare-selftest.py`.
Браузерний тест також перевіряє живий пошук Hikka, завантаження епізодів AniUA,
текстуру постера, вибір першої серії та список сезонів; йому потрібен інтернет.

Розробка GUI, автоматичного складання та тестової сцени виконувалася з допомогою
Codex. Використано Forge і WaterMedia; вони не включені до JAR мода.

У 1.3.12 каталог `videos.json` читається як UTF-8 незалежно від системного
кодування Windows. Якщо екран уже зберіг спотворену назву, вибери серію повторно.
